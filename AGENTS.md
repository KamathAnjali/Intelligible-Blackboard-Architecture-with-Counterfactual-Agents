# Repository guidance

## Documentation

- Keep a single `README.md` at the repository root. Do not add alternate or nested README files.
- Keep the README and project documentation concise, professional, and ready for external collaborators.
- Use `README.md` for the project overview, `docs/PROGRESS_REPORT.md` for implemented work, and `docs/PROJECT_MILESTONES.md` for planned work.
- Do not create a separate document for each task. Update the relevant project document instead.
- Keep project information consistent across the README and progress report.
- Do not use wording that addresses students as instructions. Describe the project and its current state directly.
- Use normal hyphens (`-`); do not use em dashes (`—`).

## Tests

- Do not create unit tests unless they are requested.

## Scope

- Treat these as guidance for future work. Do not reorganize existing documentation or tests unless the user asks.
